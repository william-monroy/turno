# 0025. Undo covers profile setup, and turno uninstall

Date: 2026-11-16. Status: accepted.

## Context

ADR 0008 journals file contents only. `turno profile add` and `turno profile repair` also make
links into the hub, replace empty folders and old links, move the person's own files to
`.aside-<time>/`, create the profile folder and write launchers. A first-run review (02-H4)
found that `turno undo last` after `profile add` restored `config.toml` and nothing else: the
links, the launcher of a profile that no longer existed and the `.aside-*` folder with the
person's files stayed, while the README promised that undo puts everything back. ADR 0021 made
`profile add` ask before moving files aside and its help said those were not undone.

There was also no way to remove turno (02-H5). The README recipe (`mcp daemon stop`, undo the
sync, delete launchers by hand, `npm uninstall`) missed the status line, the token, the config
and completion files, and was easy to get wrong. ADR 0017 already makes `mcp daemon stop`
remove the service file through the journal.

## Decision

- A journal entry has a `kind`. Besides `file` (the default, so older journals read as before)
  there are `symlink`, `unlink`, `move`, `mkdir` and `rmdir`. `Journal` performs each of these
  and records it; the path of a link is resolved through its folder only, never through the
  link. Undo applies the inverse through a new journal, so an undo can still be undone:
  - a link turno made is removed only while it still points where turno pointed it;
  - a removed link is made again only if the path is free;
  - a moved file or folder goes back only if its old path is free and it is still where turno
    put it; otherwise it stays and the step says where;
  - a folder turno created is removed only while it is empty. A non-empty one is reported as
    `kept` (not a failure, exit 0): a profile folder that holds a login is never removed.
- `setupProfiles` routes every change through a journal: the profile folder, links, moves to
  `.aside-*`, the seeded `.claude.json` and `history.jsonl`, the Codex `config.toml` and the
  launchers (`writeLauncher` and `writeHelperLaunchers` take an optional journal; a launcher
  whose text did not change is not rewritten). `profile add` passes its own journal, so one
  `turno undo` reverts the config change and the setup together. `profile repair` (and the
  doctor fix that calls it) open their own and print `undo with:`.
- `turno uninstall [--dry-run] [--yes] [--keep-config]` plans first and prints the plan, then
  asks in a terminal; without a terminal it refuses unless `--yes`. It removes, through one
  journal: the mcpd service file (and unloads it, only when the file exists in this HOME, so it
  never asks the service manager about a service it did not install), a live mcpd (SIGTERM), the
  server names `mcp-managed.json` lists in each agent config (entries turno did not write stay),
  turno's status line in the hub `settings.json` (the one the newest `ui install` journal shows
  was there before comes back), launchers carrying the `Generated by turno` marker, the fish
  completion file when it is turno's script, the gateway token, and `~/.config/turno` unless
  `--keep-config`. Shell startup lines are listed, never edited.
- It never removes profile folders, browser profiles under the data folder, turno's state
  folder (the backups that make the uninstall undoable live there) or Keychain secrets; it
  lists them. The last line names the command that removes the package: `brew uninstall turno`
  when turno runs from a Homebrew Cellar, else `npm uninstall --global turno-cli`.

## Consequences

- `turno undo <stamp of profile add>` leaves the machine as it was, except for the shared
  folders created inside the hub (`~/.claude/<item>`; launchers recreate them anyway). The 0700
  mode set on a profile folder that existed before is a `chmod` journal entry (added after this
  ADR): undo sets the old mode again unless the mode changed since.
- Pruning (ADR 0018) still keeps a journal only while one of its file backups is the only way
  back; link, move and folder entries do not hold data, so they do not keep a journal alive.
  The moved files themselves stay in `.aside-*` whatever happens to the journal.
- `turno undo` of an uninstall puts the files back but does not load the service again; the
  message after the uninstall says to run `turno mcp daemon start`.
- An entry `mcp sync` replaced (a foreign entry with the same name as a manifest server) is
  not restored by uninstall; `turno undo <stamp of that sync>` still has it.
- `uninstall` is a reserved profile name.
