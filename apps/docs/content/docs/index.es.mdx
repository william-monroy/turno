Esta página te dice qué hace turno y si es para ti, con un diagrama y dos comandos.

Cada sesión de un agente de código arranca su propia copia de cada servidor MCP. Ocho sesiones con seis servidores comunes ocupan 3,163 MiB en 56 procesos. turno arranca cada servidor una sola vez, solo cuando se llama una de sus herramientas, detrás de un gateway local que comparten todas las sesiones de todos los agentes: 847 MiB con los seis servidores corriendo y 103 MiB mientras están inactivos ([benchmark](/es/docs/benchmarks), en inglés).

<GatewayDiagram lang="es" />

Además, cada carpeta usa su propia cuenta: los repositorios del trabajo abren con tu cuenta del trabajo y lo demás con la personal.

## Qué obtienes

- **Un gateway MCP para todas las sesiones.** `mcpd` escucha en `127.0.0.1`, responde `initialize` y las listas de herramientas desde una caché, arranca un servidor la primera vez que se llama una de sus herramientas y lo detiene cuando queda inactivo. Los secretos viven en el Llavero de macOS o en el Secret Service de Linux, no en la configuración de los agentes.
- **Una cuenta por carpeta.** Con `turno profile assign ~/code/acme trabajo`, cada agente que abras en ese repositorio usa tu cuenta del trabajo.
- **Cuatro agentes, una configuración.** Los mismos perfiles, reglas de carpeta y gateway para Claude Code, Codex CLI, GitHub Copilot CLI y Cursor CLI.
- **Una status line** para Claude Code con la cuenta, su uso de 5 h y semanal, el contexto, la rama y el costo.
- **Un navegador con perfiles reales** (el paquete aparte `turno-browser`): un servidor MCP que maneja el Chrome que tienes instalado, con un perfil persistente por identidad.

## Míralo en un minuto

`turno demo` arma un HOME desechable con dos perfiles, un gateway y dos servidores MCP, abre una terminal ahí y borra todo cuando sales. No toca tu configuración.

```sh
npx turno-cli demo
```

Con turno ya configurado, `turno` solo te muestra dónde estás (la salida de la CLI está en inglés):

```text
turno 0.2.0  ~ →  personal

Here ───────────────────────────────────────────────────────────────────────────
  claude   personal   folder without a rule

Profiles ───────────────────────────────────────────────────────────────────────
              5 hours    week    account
   personal   -          -       you@personal.example · pro  default
   work       -          -       you@work.example · max

Machine ────────────────────────────────────────────────────────────────────────
  gateway   ● running on port 52222
  sessions  0 live sessions
```

## ¿Es para ti?

turno es para cuando corres muchas sesiones de varios agentes con más de una cuenta. Si solo necesitas una de esas piezas, hay otras herramientas que la hacen bien: mira la [comparación](/es/docs/comparison) (en inglés).

Funciona en macOS y Linux con Node 22.11 o más nuevo. Windows no está soportado. Nada sale de tu máquina: no hay cuenta, ni telemetría, ni proxy del tráfico con el modelo.

<Callout title="Varias cuentas y tu plan">
El uso pensado es separar cuentas de trabajo y personales. turno ejecuta la CLI oficial de cada proveedor sin modificarla, y cada cuenta sigue sujeta a los términos de su proveedor. No lo uses para sortear límites de uso ni salvaguardas. Lee [Vendor terms](/es/docs/security#vendor-terms) (en inglés).
</Callout>
