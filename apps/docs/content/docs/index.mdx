This page says what turno does and whether it is for you, in one diagram and two commands.

Every coding-agent session starts its own copy of every MCP server. Eight sessions with six common servers is 3,163 MiB in 56 processes. turno starts each server once, only when a tool is called, behind one local gateway that every session of every agent shares: 847 MiB while all six run, 103 MiB while they sit idle ([benchmark](/docs/benchmarks)).

<GatewayDiagram />

It also gives each folder its own account, so work repositories open with your work login and everything else with your personal one.

## What you get

- **One MCP gateway for every session.** `mcpd` listens on `127.0.0.1`, answers `initialize` and the tool lists from a cache, starts a server the first time one of its tools is called, and stops it when idle. Secrets live in the macOS Keychain or the Linux Secret Service, not in agent configs. See [The gateway](/docs/concepts/gateway).
- **Per-folder accounts.** `turno profile assign ~/code/acme work`, and every agent you open in that repository uses your work login. See [Folder rules](/docs/concepts/folder-rules).
- **Four agents, one setup.** The same profiles, folder rules and gateway for Claude Code, Codex CLI, GitHub Copilot CLI and Cursor CLI. See [I use Claude Code and Codex](/docs/guides/claude-code-and-codex).
- **A status line** for Claude Code with the account, its 5 h and weekly usage, context, branch and cost.
- **A browser with real profiles** (the separate package `turno-browser`): an MCP server that drives your installed Chrome with one persistent profile per identity. See [Let an agent use my signed-in browser](/docs/guides/signed-in-browser).

## See it in a minute

`turno demo` builds a throwaway HOME with two profiles, a gateway and two MCP servers, opens a shell there and removes everything when you leave. Your own setup is not touched.

```sh
npx turno-cli demo
```

Once turno is set up, a bare `turno` shows where you stand:

```text
turno 0.2.0  ~ →  personal

Here ───────────────────────────────────────────────────────────────────────────
  claude   personal   folder without a rule

Profiles ───────────────────────────────────────────────────────────────────────
              5 hours    week    account
   personal   -          -       you@personal.example · pro  default
   work       -          -       you@work.example · max

Machine ────────────────────────────────────────────────────────────────────────
  gateway   ● running on port 52222
  sessions  0 live sessions
```

## Is it for you?

turno is for the case where you run many sessions of several agents with more than one account. If you only need one of those pieces, other tools do it well: see the [comparison](/docs/comparison).

It runs on macOS and Linux with Node 22.11 or newer. Windows is not supported. Nothing leaves your machine: no account, no telemetry, no proxy for model traffic.

<Callout title="Several accounts and your plan">
The intended use is separate work and personal accounts. turno runs each vendor's own, unmodified CLI, and each account stays bound by its vendor's terms. Do not use it to get around usage limits or safeguards. See [Vendor terms](/docs/security#vendor-terms).
</Callout>
