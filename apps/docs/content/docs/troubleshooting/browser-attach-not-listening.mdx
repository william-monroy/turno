This page is for when `turno browser doctor` reports the finding below: what it means and how to fix it.

## What you see

```text
  !  attach: no Chrome with remote debugging on< for <dir>>, so the next tool call fails
```

It is a warning; warnings do not change the exit code. Words in angle brackets stand for values from your machine.

## Why it happens

An identity is set to attach to the Chrome you have open (identity.json `attach`), and no Chrome with remote debugging on was found: Chrome is closed, or remote debugging is off. Since Chrome 136 a debugging port on the default profile is ignored, so the way in is the switch at chrome://inspect/#remote-debugging (Chrome 144 and newer).

## Fix


Start Chrome, open chrome://inspect/#remote-debugging and turn remote debugging on; Chrome then asks you to allow each connection. Or turn attach off: turno browser set &lt;id&gt; --attach "".

Then run `turno browser doctor` again to see the row turn into `ok`.

The check lives in [`packages/browser/src/doctor.ts`](https://github.com/wimo-dev/turno/blob/main/packages/browser/src/doctor.ts).
